==================================================
FAST TWO-STAGE PIPELINE
==================================================

To reduce cost and runtime, use two stages.

STAGE 1:
Fast relevance filtering.

Use ONE OpenRouter model to determine:

RELEVANT
NOT_RELEVANT
UNCERTAIN

The model should determine whether the clause belongs to at least one of the 14 NDA categories.

Do NOT perform full ensemble classification during Stage 1.

STAGE 2:
Only RELEVANT and UNCERTAIN clauses go through the full three-model ensemble.

NOT_RELEVANT clauses are stored separately and are not sent to the expensive ensemble.

This is intended to reduce API calls.

BATCH PROCESSING
==================================================

DO NOT make one API request per clause.

Batch multiple clauses into each OpenRouter request.

Default:

--batch-size 25

Make this configurable.

Allow:

--batch-size 10
--batch-size 25
--batch-size 50

Start at 25.

If token limits or malformed responses occur, automatically reduce the batch size.

Every clause must have a unique source_id.

The model must return one structured result for every source_id in the batch.
